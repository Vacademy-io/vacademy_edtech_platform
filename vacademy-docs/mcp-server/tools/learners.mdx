## `learners`

**Learners: view** · Read only

Find learners by name, email or phone, and see their profile and the courses they are enrolled in, plus each course's invites and the bulk-enrol CSV template.

| Action | What it does |
| :--- | :--- |
| `find` | learners whose name, email, phone or username matches, with their courses. When several match, list them (name, email, phone, courses) and ask the admin which one — never guess. |
| `get` | one learner's full profile and enrolments — the fields learner_edit can change. |
| `enroll_options` | each course's batches and the invites a learner can be enrolled through (name, price / payment type, default or not). Ask the admin which invite to use when a course has more than one. Batches sold to organisations are marked enrollable=false (enrol those from the dashboard). Also says whether the welcome email / login-details email may be sent, and which automations run on enrolment (they may send their own welcome message). |
| `enroll_template` | the bulk-enrol CSV columns (same as the dashboard's template) as a header + sample row — hand it to the admin as a .csv file to fill in, then pass the rows (or the CSV text) to learner_enroll. |

## `learner_edit`

**Learners: edit details** · Makes changes · Changes live data — the change applies straight away. · Turned on separately (opt-in)

Let the connected AI app change a learner's details — name, phone, password, address, parents and custom fields — after showing you the before and after and getting your confirmation. Changes apply right away. Email and username can never be changed from here.

<Note>
**What keeps it safe:** confirm-gated live edit, the admin's explicit choice: changes one learner of this institute at a time; never email or username; needs the confirm_token of a preview that showed every before → after
</Note>

| `preview` | checks the change and shows each field's current → new value. Nothing is saved. Returns a confirm_token (valid 15 min). |

## `learner_enroll`

**Learners: enrol into courses** · Makes changes · Changes live data — the change applies straight away. · Turned on separately (opt-in)

Let the connected AI app enrol learners — one, a list or a CSV, existing or new — into one or more courses through the invite you pick. It always shows you a preview (who is new, who is already enrolled) and enrols only after you confirm. It asks you every time whether to send the welcome email and the login-details email, and whether you want a CSV of the learners' usernames and passwords (delivered as a private download link that expires after 30 minutes, never shown in the chat). Never removes anyone from a course. Batches sold to organisations stay dashboard-only.

<Note>
**What keeps it safe:** additive + confirm-gated: only ENROLS (never de-assigns; duplicates SKIP or ERROR, never RE_ENROLL) and only through this institute's active invites of the chosen batch; refuses organisation batches; every write needs the confirm_token of a dry-run preview of the identical request
</Note>

| Action | What it does |
| :--- | :--- |
| `preview` | checks everything and runs a dry run. Nothing is saved. Returns the per-learner outcome and a confirm_token (valid 15 min). |
| `enroll` | does it. Changed arguments need a new preview. |

```text
Enrol learners into courses through an invite — one learner or a whole list / CSV, into one or several courses at once (every learner goes into every course listed, like the dashboard's Enroll Learner dialog). Never removes or unenrols anyone. Steps: learners(action='enroll_options') for the courses → ask the admin which invite when a course has several (never pick a price for them) → preview → show the admin the outcome (who is new, who is already enrolled and skipped, which invite / price) and get a clear yes → enroll with the SAME arguments plus confirm_token. Pick an `action`:
```
