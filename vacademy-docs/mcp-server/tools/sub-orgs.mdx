## `sub_orgs`

**Sub-organisations: view** · Read only

See the institute's sub-organisations (partner organisations / centres): each one's admin, courses, seats used against the cap, plan status, invite link and learners, plus the payment options and roles a new one can be set up with.

| Action | What it does |
| :--- | :--- |
| `list` | every sub-org with its admin, plan status, seats used / total and invite code. When several match a name, list them and ask which one. |
| `get` | its courses (batches), seats used per course against the cap, admins, the settings it was created with (admin roles, team roles, admin permissions, validity, payment option) and the admin's invite link. |
| `members` | its learners with their courses and status. |
| `create_options` | what sub_org_edit(change='create') needs — the institute's payment options (with prices), payment gateways, the roles a sub-org admin can be given and the admin permissions. The courses come from courses(action='list'). |
| `enroll_template` | the CSV columns sub_org_enroll takes (with the institute's custom fields) as a header + sample row — hand it to the admin as a .csv file to fill in. |

## `sub_org_enroll`

**Sub-organisations: add learners** · Makes changes · Changes live data — the change applies straight away. · Turned on separately (opt-in)

Let the connected AI app add learners — one, a list or a CSV — to a sub-organisation's courses. It always shows you a preview (who is added, who is already in and skipped, seats left) and adds them only after you confirm, never past the sub-organisation's seat cap. Adds learners only — never admins — and never removes anyone. It asks whether you want a CSV of the learners' usernames and passwords (a private download link that expires after 30 minutes, never shown in the chat).

<Note>
**What keeps it safe:** additive + confirm-gated: only ADDS learners (role LEARNER, never admin) to the courses of a sub-org of this institute; skips anyone already active in a course; refuses uploads over the sub-org's seat cap; every write needs the confirm_token of a preview of the identical request
</Note>

| Action | What it does |
| :--- | :--- |
| `preview` | checks everything; nothing is saved. Returns the per-learner plan and a confirm_token (valid 15 min). |
| `enroll` | does it, learner by learner, and reports each one. |
