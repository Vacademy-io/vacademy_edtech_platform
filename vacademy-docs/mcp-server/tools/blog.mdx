## `blog`

**Blog: view** · Read only

See the institute's blog posts — drafts and published articles, their bodies and SEO fields, and which website pages show them.

| Action | What it does |
| :--- | :--- |
| `list` | posts newest-edited first with status, slug, category, author, publish date and where they are shown. status is PUBLISHED, DRAFT, ARCHIVED or ALL (default ALL). |
| `get` | one post with its full HTML body, SEO fields and public URL(s). |
| `placements` | which website pages carry a Blog section (site, page route, public URL) — where a published post appears. If none, tell the admin to add the Blog block to a page. |

## `blog_edit`

**Blog: draft posts** · Makes changes · Drafts only — nothing goes live until someone publishes it in the admin portal.

Let the connected AI app write blog posts by conversation and save them as DRAFTS in Manage Pages → Blog. A draft is never shown on the website until you open it and press Publish; published posts cannot be changed or removed from here. Uses no AI credits.

<Note>
**What keeps it safe:** draft-only: create forces status=DRAFT (never served publicly); update/discard refuse anything that is not a DRAFT; request_publish only returns the dashboard link — publishing is an admin click
</Note>

| Action | What it does |
| :--- | :--- |
| `create` | saves a new DRAFT post. content_html is the article body as HTML (headings h2/h3, paragraphs, lists, blockquotes, tables, images from the institute's own media URLs, YouTube/Vimeo embed iframes). Write a real excerpt (1–2 sentences) and a meta description; both show on cards and in search results. |
| `update` | changes a DRAFT post. A PUBLISHED post cannot be changed from here — tell the admin to unpublish it in the dashboard first, or create a new draft. |
| `request_publish` | checks the draft (title, excerpt, body length, SEO, cover) and returns the dashboard link where the admin publishes it. Never claim a post is live. |
| `discard` | deletes a DRAFT post — the undo for a draft this app created. |
